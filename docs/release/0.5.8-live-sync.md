# Pocket Composer 0.5.8 · 连续输入实时跟随 / Live sync

> Windows 稳定版发布说明。以下性能数据来自隔离环境的自动化探针（无头 Chromium + offscreen Qt），不代表实体手机或用户验收。

## 中文

本版包含连续输入同步修复，并补齐凭据清理失败提示：系统凭据已写入但旧明文文件删除失败时，设置界面明确提示，重新保存可重试。首页与安装指南版本入口保持一致。

- **连续输入时电脑持续跟随**：手机本地保存改为“只等自己这一份”。以前持续说话时，发往电脑前的本地写盘会被后续输入一直拖住；在模拟慢存储的浏览器中，电脑浮窗曾落后 2–9 秒，现在约 0.3 秒。本机回环自动化环境下每次同步从约 115 ms 降到约 25 ms；这不是实际 Wi-Fi 时延承诺。
- **带图写字不再每个字重写图片**：图片原图、成品和画布场景在手机里只写一次，之后每次保存只写文字级别的数据；带三张图时单次保存从约 44.6 万字符降到约 1 万字符。离线稿、清空恢复、多标签接管副本仍完整保存。
- **等待确认时提前保存下一份**：电脑确认上一份后，已保存好的下一份立即发出。
- **状态如实显示**：手机区分「实时同步中」和电脑已收到；超过 1.5 秒未获电脑确认时提示「电脑还没收到最新 N 秒 · 稿在手机」。
- **电脑侧不积压**：浮窗只渲染最新一版；「当前图文」窗口在手机更新时保留阅读位置和选区，图片未变不重新读取。电脑校验过的图片不再每句重新解码。
- **长稿术语提示**：长稿不再因请求过长而失败。
- **快速输入不断同步**：手机每 0.1 秒最多发一份最新稿（停顿后的第一份立即发），最后一版总会送达；电脑连接限速时手机自动稍后补发，不再显示“草稿有分歧”而停住。
- **选中文字时浮窗仍更新**：在浮窗里选中或停在前文阅读时，后面新说的内容照常出现，选区和位置不动（含 emoji）；只有新内容要改到选中的那段时才暂缓，并提示「新内容已到 ↓」。
- **电脑保存时定时刷新不再等待**：保存手机稿时，检查面板等定时读取不再等待写盘。电脑主动改字和复制附注等需要当前稿件的操作仍可能等待正在进行的存盘。
- **新旧版本页面共存**：手机本地草稿库升级到新版本号。仍开着的旧版页面会断开本地存储并提示不可用，不会把新格式误当图片读出再写回；刷新即用新版。
- **审查修复**：多标签接管时比较完整的图片编辑内容（白板场景、画布文字等），不同就另存；电脑重启后未完成的图片上传可按原编号续传，过期或无效的残留分块有界清理（只清理本程序自己的上传目录）；Linux 无障碍角色中的终端/代码身份会被识别；从显式文件模式迁回系统凭据库后删除旧明文。

保持不变：插入不按 Enter，模型检查不阻挡同步和插入，用户向上翻看时不被顶到末尾，按稿件身份处理回执，图片先于文字。

### 升级与回退

升级电脑程序后刷新手机页面。若旧标签页仍有尚未保存的输入，先复制保留，再刷新。新版将此站点的本地草稿数据库升级为版本 2；回退电脑程序到 0.5.6 后，旧网页无法读取这个库，会提示存储不可用。不要清除浏览器站点数据来消除提示；重新使用 0.5.8 页面仍可读取这些稿件。

### 验证范围

本轮覆盖生产网页输入、真实 IndexedDB、实际 Qt 离屏控件、慢存储、长文、选区、高频输入与跨版本存储。实体手机输入法、实际 Wi-Fi、多屏和用户日用目标应用尚未完成本候选验收。Windows 安装与原生输入结果以对应源码提交的候选构建报告为准。

## English

- **Desktop keeps up with continuous dictation.** Local saves before sending now wait only for their own snapshot. Previously, continuous input could starve the pre-send save; on a simulated slow phone store the desktop overlay lagged 2–9 s, now about 0.3 s. In the local loopback benchmark each update arrives in about 25 ms instead of about 115 ms.
- **Images are no longer rewritten on every keystroke.** Original photos, rendered images and canvas scenes are stored once; later saves write text-sized records (about 10k instead of 446k characters with three images). Offline drafts, clear/restore and multi-tab copies remain complete.
- **Pipelined sending and honest status.** The next snapshot is saved while waiting for the desktop acknowledgement. The phone distinguishes live syncing from acknowledgement and reports a delay after 1.5 s without acknowledgement.
- **No desktop backlog.** The overlay renders the latest version only; the review window keeps the reading position and selection; verified images are not decoded again for every update.
- **Fast typing stays connected.** At most one snapshot per 0.1 s (the first after a pause is immediate); the final version always arrives, and a desktop rate limit triggers a quiet resend instead of a conflict.
- **Overlay keeps updating while you select text.** New text after the selection appears; selection and scroll stay put (emoji-safe). Only changes that touch the selection wait behind a “new content” button.
- **Periodic UI reads no longer wait for desktop disk writes** during phone updates. Explicit editing and operations that require the current draft can still wait for an ongoing save.
- **Mixed versions are safe.** The phone draft database moves to version 2; an old page that is still open loses storage access instead of misreading new records.
- **Review fixes:** full image-edit comparison for tab takeover, restart-safe resumable uploads with bounded cleanup that never touches unrelated folders, Linux terminal/code accessibility roles, and plaintext removal after migrating to the OS keyring.

Insertion still never presses Enter, model checks never block sync or insertion, and scrolling up is never overridden.

After upgrading, copy any unsaved input from old phone tabs before refreshing them. The phone database upgrades to version 2. Version 0.5.6 cannot reopen that database after a downgrade; keep the site data and use the 0.5.8 page to recover those drafts. Timing figures above come from local automated tests, not physical phones or real Wi-Fi acceptance.
