# 安装与使用 Pocket Composer

> 仓库现已更名为 [Pocket-Composer](https://github.com/aaakoako/Pocket-Composer)。新版从此仓库检查更新；仍指向旧仓库的旧客户端可手动下载安装。现有数据目录保持不变。

**当前 Windows 稳定版：0.5.8**（[发布说明](0.5.8-live-sync.md)）：改进手机连续输入时电脑跟随的速度与状态提示。macOS/Linux 仍为体验版，见 [跨平台说明](CROSS_PLATFORM.md)。

安装包和便携包包含同一套 Windows 客户端与手机页面。下载文件名保留旧标识 `DoubaoTypeless_<版本>_win_x64_Setup.exe` 供更新器识别，产品名称为 Pocket Composer。版本标注“发布候选”时，仍需完成真实手机和目标输入框验收；这不代表已经公开发布。

## 开始使用

1. 从旧版托盘正常退出，保留旧目录和数据。
2. 从 [Releases](https://github.com/aaakoako/Pocket-Composer/releases/latest) 下载并运行 `DoubaoTypeless_<版本>_win_x64_Setup.exe`（当前稳定版为 0.5.8）。仅为当前 Windows 用户安装，无需管理员权限。以后从开始菜单打开 **Pocket Composer**（安装目录与可执行文件名仍为 DoubaoTypeless）。
3. 手机与电脑接入同一网络，扫描电脑连接页的二维码。地址和端口以该页为准，不沿用旧预览端口。
4. 在电脑连接页允许手机插入。点一下 Codex/Cursor 的对话输入框，再用手机说话、加入图片，点“插入电脑”。插入不会自动发送消息。
5. 插入后手机可开始下一段。需要上一段时使用“恢复”；不要重复点插入来猜测图片是否已经进入目标。

浮窗标题可以拖动；阅读旧文字时不会强行滚到底部，「当前图文」窗口在手机继续输入时也保留阅读位置和选区。手机连续说话时显示「实时同步中」；超过 1.5 秒电脑未确认会提示落后秒数，稿件始终先保存在手机。展开后可以返回浮窗，设置窗口和浮窗可同时显示。白板文字在页面内编辑，可以取消；手机返回键会关闭当前面板，未保存白板会先询问是否放弃。

## 数据与升级

### 从 0.4.2 或更早版本过来

这次是框架级升级：完整替换程序，旧配置、词库、历史保留在旧目录，不自动迁移，新版需要重新配置和扫码。

发布的 `DoubaoTypeless.exe` 是包含全部运行文件的原生升级入口。0.4.2 的更新器下载后仍按原来的方式替换旧 EXE；新入口会部署完整新版并打开它。它不依赖已退出旧程序的 Python 临时目录。旧快捷方式再次打开时会转到已安装的新版，不重复解压。

也可以下载当前版本的 `DoubaoTypeless_<版本>_win_x64_Setup.exe` 手动安装。发布候选尚未公开时，旧版“检查更新”不会发现这个候选，需要手动打开候选升级入口；不要据此判断更新检查故障。

单文件入口与 Setup 包使用同一原生载荷，因此旧客户端无论选中哪份 EXE，重命名后都进入完整升级流程。请保留旧目录的 config.json 和 data，以便以后按需导出内容；不删除它们来排障。

### 已使用新版固定工作区的安装之间升级

正式安装与发布候选默认使用 `%LOCALAPPDATA%\DoubaoTypeless\workspace-v3`，不随安装版本目录变化。旧预览数据与旧版 `config.json` 不会自动导入或覆盖。需要保留已有预览内容时，先在原版本完成当前稿或导出词库；不要直接把多个版本的数据目录混在一起。

设置中的“数据与备份”可以打开当前目录。升级首次启动会在 `upgrade-backups` 保存当前草稿、图片、设置、恢复记录及本地持久文件；SQLite 通过备份接口保存。只把含有 `backup-complete.json` 的目录视为完成备份。正常安装的 API Key 存在 Windows 凭据库，文件备份不包含该密钥；固定工作区内升级会继续使用已有凭据。

新版设置中的“检查更新”发现正式版本后，可以点“下载并重启更新”。完整下载和校验通过后才交接退出；新版启动就绪后才切换安装入口。下载失败仍使用当前版本，升级交接超时会撤销本次操作；已安装版本的解压或启动失败会尝试重新打开旧程序。安装目录中的 `versions` 按版本和构建标识分开保存，会保留此前安装的程序，便于回退同一数据格式的版本。未来数据格式不兼容时，旧版本会拒绝修改数据。

0.5.9 起，安装会创建桌面和开始菜单快捷方式，安装完成页默认勾选“打开 Pocket Composer”；静默安装不额外启动。客户端启动后自动检查一次，此后每 6 小时检查；发现新版本时显示独立更新窗口，同次运行不重复提示相同版本。网络失败或已经最新时保持安静，手动检查会显示结果。下载与安装仍由你点击确认。

同时开启 Tailscale 或其他 VPN 时，连接页优先显示已连接的局域网网卡地址。多网卡可以在地址下方切换，二维码和复制地址随之更新；切换 Wi-Fi 后点“刷新网络地址”。选择 Tailscale 地址时，手机也需要接入同一虚拟网络；局域网地址仍要求手机与电脑之间可达。

需要恢复备份时，退出程序，保留当前工作区副本，再把一份完整备份放到独立目录，用程序的 `--data-dir` 参数打开核对。凭据与 Windows 账户及工作区路径绑定，换目录或换账户后需要重新填写 API Key。不要在运行中覆盖工作区。

卸载只移除程序和当前安装对应的入口，保留用户数据。文件被占用时会提示退出程序后重试，并保留卸载入口。便携包解压后直接运行 `DoubaoTypeless.exe`，同样使用固定工作区。

## 遇到问题

- 找不到输入框：先手动点一下目标对话框，再插入。若已复制，可以在目标按 Ctrl+V；不要按 Enter 试探。
- 图片接收待确认：查看目标中已有图片，使用“恢复”处理剩余内容，避免重复插入。
- 手机断线：草稿在手机本地保留，电脑已收到的稿仍可使用。勾选“记住这台手机”后，等手机提示“已记住”，在同一浏览器、同一电脑地址下，30 天内会自动续接；暂时断网或电脑未启动不会要求重新配对。
- 配对存储：清除浏览器数据、换浏览器或换电脑地址/端口，需要重新扫码。无痕浏览器可能无法长期保留凭据；电脑主动撤销或配对过期也需要重新扫码。旧版已丢失的手机凭据无法凭设备名字恢复。
- 版本不一致：核对电脑连接页和手机设置中的版本号及提交标识，退出旧程序后重新扫码。
- 升级失败：保留数据和 `upgrade-backups`，使用“导出诊断”提供错误记录；不要删除工作区来解决启动问题。

开发者构建说明见仓库 `docs/release/v3-build.md`。

升级日志位于安装目录的 `upgrade.log`。从旧单文件版本更新时，旧目录的 `update.log` 记录旧更新器的退出和替换阶段。0.4.2 自身在下载或退出阶段的既有故障无法通过服务器反向修改；遇到这种情况可手动运行完整升级入口。

## 输入检查与动效

在「常用设置」开启 Jev 输入检查，可选择 TypeSafe、Vercel、OpenRouter 或 TypeSafe 兼容的自定义服务。填写对应 Key 并检测连接。纠错与改写使用独立模型配置，支持 OpenAI 兼容地址；可填写 Base URL 或完整接口，保存前会补全常见格式。

输入检查只发送当前文字。浮窗用图标和短标签提示疑似误字、歧义、缺项及语气，展开查看原句。附注只说明文字可能有误，不要求目标模型追问；可为当前段落关闭。检查失败不会阻挡插入。

界面动效默认开启，独立于 Windows 的减少动态效果设置。电脑常用设置与手机设置分别提供关闭入口。明确生气的语气会触发短暂火焰，随后保留暖色边框；语气标签不代表对真实情绪的判断。

## 历史版本说明

以下为早期版本的发行记录，保留供查阅；当前安装请以本页开头的版本为准。

曾安装内部 0.5.1/0.5.2 候选的用户，请手动运行 0.5.4 或更新版本的完整安装入口。内部候选的更新入口可能不同，建议手动运行完整安装包。公开 0.4.2 升级到 0.5.4 不受此影响。

0.5.0 在依赖扫描告警后已撤回草稿，正式修订使用 0.5.4。已下载过 0.5.0 的用户应升级至修订版，不继续分发旧包。

0.5.1 正式构建在焦点变化后立即重试的场景失败，未公开发行。0.5.2 将重试结果提示放在操作队列释放之后，并对忙碌拒绝给出反馈；不自动排队重贴。

0.5.2 正式构建因故障恢复验证超时和图文焦点恢复检查失败而未发行。0.5.3 区分本应用注入与外部输入，并在原附件容器内有限恢复焦点；不因自身粘贴改变输入时间戳而误判用户切换，也不重贴图片。故障恢复检查保持原断言和时限，使用独立一次性 Windows 环境并保留超时证据。

0.5.3 候选曾完整通过，但正式构建在定位输入框后的焦点验证失败，因此未发行。0.5.4 不重复抢焦点，在短时间内只读复核同一个控件，并记录定位失败与退出的具体阶段。
