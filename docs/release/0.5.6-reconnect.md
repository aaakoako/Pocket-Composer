# 0.5.6 手机自动续接修复候选 / Reconnection candidate

本版是修复候选，尚未公开发布为正式更新。不替换已发布的 0.5.5 文件。

## 修复内容

- “记住手机”的凭据收到后必须在浏览器存储成功，手机才确认保存。响应丢失可以重取，电脑显示等待保存状态，避免显示已经记住却无法续接。
- 电脑重启后，手机用持久凭据获取新会话，沿用原设备身份、插入和截图权限。临时网络失败、超时或服务暂未启动会自动重试，不弹出配对框。
- 多次唤醒和点击连接共享一次续接请求。同一浏览器重新打开页面或再次扫码，优先续接原设备；电脑授权列表按设备合并显示。
- 主动撤销或过期仍要求重新配对。凭据文件改为原子保存，服务器只持久保存凭据的哈希。

## 验证与边界

使用正式构建的手机页面、隔离桥接服务与无头 Chromium，覆盖凭据响应丢失、断网恢复、认证服务从磁盘重建后的续接、503 重试、新标签页再次扫码、存储拒绝与设备撤销。验证草稿、设备身份、权限及授权列表保持正确。

全量源码回归：715 passed，2 skipped。TypeScript 检查及生产页面构建通过。真实 iOS/Android 的浏览器后台冻结、扫码应用内浏览器与跨 Wi-Fi 切换仍需实机验收；这些不能由无头浏览器代替。

Windows 候选来源：`221500b13712e0b6af183352cf6b0bb391b26e92`。本地安装包与便携包位于 `G:\AgentStorage\Deliveries\PocketComposer-0.5.6-reconnect`，启动/正常退出通过。额外使用打包 EXE、隔离桌面和正式手机页面，验证电脑真正退出后重新启动，手机身份不变、断线期间新增文字同步且不弹出配对框。便携包 1022 个文件逐项核对大小与 SHA256，安装包及便携包总摘要通过。未执行本轮真实用户安装升级。

浏览器配对凭据属于当前地址（含端口）及浏览器。清除网站数据、换浏览器或换地址后需要扫码。旧版已经丢失的凭据不能用手机名字或 IP 猜测恢复。

## 发布前审查修复（源码已改，尚未打包）

基于 `e5604f8` 的隔离分支 `fix/opus55-product-review`，版本号不变，没有重新打包，也没有覆盖旧候选包。

- 正文、图注或电脑回执里出现 PowerShell、cmd.exe、shell 等词都按普通内容处理。手机消息改为按类型检查字段结构，顶层 keys/vk 等按键脚本仍会被拒。错误回包带原请求编号，同步不会再无限重发。
- 第一次因没选中输入框而未插入（NO_STEPS）时，用户再点一次可以重试。已可能送达的结果（未知、部分完成、已确认）绝不自动重贴。每次点击都换新 nonce，网络重传不能重复注入。
- 重新扫码时，同一浏览器若持有仍有效的旧会话证明，会沿用原设备身份和权限；设备号或名字本身不算证明。电脑重启后失去证明的手机会成为新设备，草稿里的图用手机本地原图自动重传。本地没有原图时，需要在电脑连接页明确批准才能取回旧图；原手机在线时一律拒绝。
- 配对输错有限流：同一来源连续输错会被锁定，锁定时间逐次加长，接口返回 429 和剩余秒数。猜错不会作废当前二维码。4 位备用短码累计输错后停用，只有在电脑上点「重新配对」才恢复。窗口隐藏时不再生成新配对码。
- 手机本地草稿读不出来时，不再把空稿写回覆盖。页面会提示「重试读取」或「先写新稿」；新稿另存一份，旧稿保留，之后可在「最近」恢复。
- 同一手机开多个标签页时，只有当前页面写入本地主稿。被接管的页面暂停写入并断开连接，它的不同内容另存，可恢复。回到该页或点「在此页继续」时，先读入最新稿再接着写。电脑向这台手机取稿时询问它的所有页面，旧页面不会挡住当前页。
- 手机主稿冲突时可以选「采用电脑这份」：先保全手机稿，再接续电脑镜像。另一台仍在线手机的图不会被带过来。
- 「记住 30 天」「取消记住」和昵称都只作用于一台手机。电脑没能写入设备信任时，不向手机暴露凭据，也不显示已记住；授权变更、撤销和取消记住在写盘失败时都会回滚，并提示可以重试。
- 管理接口只接受本机、同源（端口一致）的 JSON 请求，手机的局域网连接不受影响。图片编号限制为安全字符，读取不能越出资产目录。
- 退出等待超时时，当前版本继续可用：队列、热键和插入都恢复。升级备份不再复制可重新下载的更新缓存；备份失败会删除未完成的备份，旧的暂存包会自动清理；升级就绪等待延长到 120 秒。
- 已有手机稿时，连接页练习框会收起，不再生成隐藏的电脑副本。截图只发给在线、未过期、有截图权限的当前手机；目标不明确或没有权限时会提示。
- 插入回执先存到电脑磁盘，再通知手机。通知失败、手机断线或电脑重启后，手机重连仍能取到「已插入」，不会把同一稿当作未发再发一次。电脑重启后，同一次插入依然按原结果判重；中途退出的插入按「结果未知」处理，绝不自动重贴。回执没能存下时会如实告诉手机：「请先在电脑上确认，勿重复插入」。
- 页面被另一个标签页接管时，刚说完、还没来得及保存的最后一句和打开中的编辑都会另存。接管回来时，若另一页没改过稿，这些内容直接回到编辑区；改过就保留较新的主稿，这份放进「最近」。
- 另一个标签页刚换了新配对时，旧页面迟到的失败不会删掉新凭据，迟到的成功也不会覆盖新凭据或新会话证明。会话失效时只撤掉它自己的证明。
- 连接页版本行在源码运行时显示「开发构建」，不再截成半个词；字号大或窗口窄时自动换行。
- 电脑窗口和手机请求同时更改设备信任时（例如两台手机同时点「记住」，或一台记住时另一台被撤销），改动依次写盘，不再出现后写的覆盖先写的、重启后少一台已记住的手机。

验证：全量源码回归 805 passed、2 skipped（上一段为 783）；TypeScript 检查和生产页面构建均通过。其中单元/接口测试和真实 Chromium 生产页面流程分开统计，页面流程中的系统投递是测试替身。冻结 EXE、真实手机（多标签、后台冻结、Wi-Fi 切换）以及真实 Cursor/Codex 输入框都还没有在本轮验证，不能视为用户验收通过。

## English

This is a 0.5.6 candidate, not a published stable update. Published 0.5.5 assets remain unchanged.

Remembered credentials remain retrievable until the phone confirms durable browser storage. Transient reconnection failures retry without forcing pairing. Restoring authentication from disk retains device identity and grants; repeated wake/connect requests share one resume attempt, and the desktop shows one entry per device. Revoked or expired credentials still require pairing. Trusted-device records are written atomically and contain secret hashes only.

Production-page browser regressions cover lost responses, offline recovery, reconstructed authentication, temporary server failure, rescanning in another tab, storage denial and revocation. The source suite passed 715 tests with 2 skips. Physical iOS/Android background suspension, embedded scanner browsers and Wi-Fi switching remain unverified. Changing browser/origin or clearing site data requires pairing again.

The figures above and the `221500b` package predate the pre-release review fixes below.

### Pre-release review fixes (source only, not packaged)

- Phone messages are validated by type and field structure. Words such as PowerShell or cmd.exe in text, captions or receipts are content; error replies carry the request ids.
- A NO_STEPS insert can be retried by an explicit second click. Possibly delivered results are never replayed, and every click uses a fresh nonce.
- Re-pairing keeps the device identity only with a still-valid previous session proof. Otherwise images are re-uploaded from the phone, or recovered after explicit desktop approval (refused while the original phone is online).
- Pairing failures are rate-limited per source (429 with Retry-After) without invalidating the QR code. The short code is disabled after repeated failures until the user re-pairs on the desktop, and hidden windows no longer mint challenges.
- A failed local draft read never writes an empty draft; retry and a separate new draft are offered. Multiple tabs on one phone use a writer claim, paused tabs keep their differing content recoverable, and desktop preparation asks every tab of the device.
- "Use the desktop copy" works for phone-primary conflicts. Remember/unremember and nicknames are per device. Trust changes are committed to disk before taking effect, and roll back on failure.
- Admin routes require same-origin loopback JSON. Asset ids are restricted, a timed-out quit restores the queue and hotkeys, and upgrade backups skip the update cache and remove partial backups.
- Insert receipts are written to disk before the phone is notified. Reconnects and desktop restarts still return the delivered receipt, and insert results are persisted so the same intent is never replayed after a restart; an insert interrupted mid-way is treated as unknown. A receipt that could not be saved is reported to the phone, not presented as a safe retry.
- A tab taken over by another tab keeps its not-yet-saved last input and any open editor content as a recoverable copy. Taking the tab back restores that copy only if the other tab did not change the draft.
- A stale tab's late resume response, failure or success, no longer deletes or replaces credentials written by another tab. A revoked session forgets only its own proof.
- The version line shows "开发构建" (development build) for source runs instead of a clipped word, and wraps when the window is narrow or the font is large.

- Trust changes from the desktop window and phone requests are serialized, so concurrent remember/revoke/grant actions can no longer overwrite each other's saved devices.

Source suite: 805 passed, 2 skipped (previously 783); typecheck and production build passed. Frozen EXE, physical phones and real Cursor/Codex targets are not verified for these fixes.
