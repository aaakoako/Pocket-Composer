本轮基于 `e5604f832e7a58bff5e57166bd5cd0b8aa7764e9`，由 Cursor 的 **Claude Opus 5.5 300K High** 实现，Codex 独立审查、复现和验收。经过五轮实现与复核，本地主审通过，远端候选构建待复跑；正式发布与实机验收尚未完成。

## 已解决的问题

- 记住手机与续接：凭据保存确认、同设备身份、过期或撤销、失败回滚、多个设备的独立授权，以及 Qt/HTTP 同时修改信任记录时的覆盖。
- 手机草稿：读取失败不会空写覆盖；同一浏览器多标签页只有当前页写主稿；切换前尚未保存的文字及编辑内容保留为可恢复副本；可以明确采用电脑镜像。
- 插入：技术术语不再被误判为按键脚本；没有执行任何步骤时允许再次点击；已经投递或结果不确定的意图跨重启去重；回执先保存再发送。
- 图片、连接与安全：新身份重新上传本地原图；缺少原图时由电脑批准取回；限制素材路径及设备归属、管理接口来源和短码尝试；增加连接心跳。
- 桌面与升级：退出失败恢复队列及热键；练习框不覆盖手机稿；截图选择当前有效设备；升级备份排除下载缓存；设备控制分开显示，大字号版本说明换行。

Jev 仍是可选功能，情绪与火焰动效保留。主路径仍为图片后接文字，插入和重连不会自动按 Enter。

## 提交后的 CI 回归（本地主审已复核）

`33fe6c9` 在 GitHub Release workflow run 36837249823 中，Windows 源码套件失败 1 条（805 通过、1 跳过），Linux 与升级恢复通过，打包已正确跳过。失败用例为 `test_takeover_back_keeps_newer_current_and_side_copies_pending_text`：接管回来后没有找到“最后一句”的副本。

已查明两点：

- 用例夹具只拖住了本地写盘的 120ms 防抖，没有拖住外发前也会写盘的 100ms 防抖。CI 上另一页打开较慢，这句在接管前已作为主稿正常写入，并显示在新页面，于是不存在“未保存的内容”。
- 代码确有一处相关缺陷：页面被接管、写入被拒时，草稿仓库会丢掉排队中的更新快照，副本只留下较旧的一份。

两者都已在未提交的 segment-04 中修正：本地 810 通过、2 跳过，Codex 25 项通过。主审已用提交原文件独立复现排队快照缺陷，并在修正后验证通过。远端构建仍须用补修后的精确 HEAD 重跑，旧构建失败记录保留。详见交付目录下的 `segment-04/implementation.md`。

## 终审补充：接管时另存失败（本地主审已复核）

复核同一接管路径时又确认一处丢稿：被接管时本页内容另存失败（如存储已满）的错误被吞掉，点「在此页继续」后读入了另一页的新稿，并提示内容“已放进「最近」”，实际没有副本。现已改为：确认另存成功之前不接管、不读入，保持暂停，内容留在页面上可复制，并可在腾出空间后重试。修正在未提交的 segment-05 中：本地 812 通过、2 跳过，Codex 6 个文件 27 项通过。主审已重新运行27项独立用例（包括真实写失败后恢复存储再重试），全部通过，并检查了320px失败提示截图。远端构建与冻结包仍待验证。详见 `segment-05/implementation.md`。
